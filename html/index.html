What is a sysext?

A systemd-sysext is a read-only disk image holding files for /usr (and optionally /opt). When it is merged, those files appear inside the running system as if they were installed, and unmerging removes them again. Nothing is written to the base OS.

Flatcar Linux has an immutable base system and no package manager, so sysexts are how you add tools such as Docker, Kubernetes or Tailscale. Each extension is self-contained and updates on its own schedule, separately from the OS. You enable one with a few lines of Ignition config at first boot, and systemd-sysupdate fetches new versions after that.

This is an expanded fork maintained by Quantum Operations of flatcar/sysext-bakery. The build system and most extensions come from the Flatcar maintainers and community, and we are grateful for their work. We add extensions of our own and host the results on our own hub.

Use it on a node

Replace NAME with an extension from the list. Ignition downloads the image at first boot. The extra sysupdate files let the node check this hub for new versions. See each extension's documentation for the full snippet.

Install an extension

storage:
  files:
    - path: /opt/extensions/NAME/NAME-1.2.3-x86-64.raw
      contents:
        source: https://extensions.quantumops.consulting/extensions/NAME-1.2.3-x86-64.raw
  links:
    - path: /etc/extensions/NAME.raw
      target: /opt/extensions/NAME/NAME-1.2.3-x86-64.raw

Allow updates to run

systemd-sysupdate refuses to start when /etc/sysupdate.d is empty. This one placeholder file fixes that.

storage:
  files:
    - path: /etc/sysupdate.d/noop.conf
      contents:
        source: https://extensions.quantumops.consulting/extensions/noop.conf

Each extension also has its own update file at https://extensions.quantumops.consulting/extensions/NAME.conf, and the version list for this page is manifest.json.
